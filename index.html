CASE #001DISK · $MFT · MEMORY FORENSICS
v0.1.0
Python 3.11+ · No runtime dependencies · NTFS · Volatility 3 (optional)

forensic-evidence-toolkit

Forensic imaging with streaming hashes and a chain-of-custody record, an NTFS $MFT parser (attribute lists, extension records, timestomp heuristics) and a Volatility 3 triage wrapper. The $MFT output had 0 differences against an independent parser (dfir_ntfs) on 25,408 real records, and 12,171 reconstructed file paths were identical to The Sleuth Kit's fls. Imaging a real block device produced the same SHA-256 as sha256sum.

Not yet verified: memory triage was checked against the Volatility 3 source code only, not run on a real memory image; the timestomp heuristics flag many legitimately installed files, so they are leads, not proof.

CASE #002WINDOWS INCIDENT RESPONSE & FORENSICS
v0.2.0
Python · Sigma-subset rules · MITRE ATT&CK · Bilingual EN/AR

win-ir-triage

Parses EVTX logs, evaluates 10 Sigma-subset rules mapped to MITRE ATT&CK, and writes a bilingual (EN/AR) HTML timeline plus JSON and ATT&CK Navigator exports. Run over all 278 files of the public EVTX-ATTACK-SAMPLES dataset: 0 parse errors, 37,364 events, event counts identical to the dataset's own index, and 16 of 16 hand-labelled expectations passing (the labels were chosen after seeing results, so this is not a blind test).

Not yet verified: the false-positive rate (the dataset contains attacks only) and detection of attacks the rules were not written for.

CASE #003SMART CONTRACT STATIC ANALYSIS
v1.1.0
CLI · Static analysis · Docker · Zero dependencies

smart-audit

Static analyser for Solidity with 18 SWC-mapped rules; five of them read the structure of each function (reentrancy, unchecked calls, unprotected selfdestruct, missing zero-address check, missing event) instead of matching text. HTML, JSON and Markdown reports with a per-contract score, and exit codes for CI. Pattern-based and noisy by design: a first pass, not a replacement for a manual audit.

Not yet verified: behaviour on large real-world contract codebases; it performs no data-flow or cross-contract analysis.

CASE #004EVM NODE SECURITY AUDIT
v0.2.0
CLI · JSON-RPC · Geth & Nethermind configs · Docker

BlockSec Auditor

Read-only auditor for Ethereum/EVM nodes: RPC exposure, admin and wallet APIs, CORS, TLS, client version against a curated advisory list, and Geth/Nethermind configuration files. Every outcome is PASS, FAIL, ERROR or SKIPPED; an unreachable node is never reported as clean. The advisory list matched Geth's own advisory data on 241 real releases, and the config audit ran on 91 real Nethermind configs without errors.

Not yet verified: no live node has been scanned yet; the RPC checks are covered by tests against a mock server only. Only Geth has verified advisory data.
